 COMPARACION
==============================================================================

  canal          bytes   vs. web    tiempo   para que sirve
  --------------------------------------------------------------------------
  web              979     100 %      9,3 ms   ficha completa con agregados
  movil            340       35%     10,2 ms   saldo y ultimos movimientos
  cajero            43        4%      5,7 ms   solo saldo disponible

  Los tres leen la MISMA cuenta del mismo modulo de dominio. La diferencia

==============================================================================
 INVENTARIO DE APIS - cada endpoint de los tres BFF
==============================================================================

  canal  endpoint                                   estado       bytes  autenticacion
  ----------------------------------------------------------------------------------------------------
  web    GET  /api/web/cuentas                      200 OK       48614  JWT web (rol EJECUTIVO)
  web    GET  /api/web/cuentas/{id}                 200 OK         979  JWT web
  web    GET  /api/web/cuentas/{id}/estado-anual    200 OK         162  JWT web
  web    GET  /api/web/transacciones                200 OK        1418  JWT web
  movil  GET  /api/movil/cuentas/{id}/resumen       200 OK         340  JWT movil
  movil  GET  /api/movil/cuentas/{id}/movimientos   200 OK         281  JWT movil
  cajero POST /api/cajero/sesion                    200 OK         252  terminal + PIN -> JWT
  cajero GET  /api/cajero/saldo                     200 OK          43  terminal + JWT cajero
  cajero POST /api/cajero/retiro                    HTTP 400         0  terminal + JWT cajero

  Nueve endpoints en total: cuatro del canal web, dos del movil y tres del
  cajero. La cantidad no es casual y es en si misma parte de la evidencia:
  el canal con mas superficie es el que corre en un equipo de confianza, y el
  que entrega dinero en la calle expone lo minimo para operar.

  El 400 del retiro es la respuesta ESPERADA y no un fallo: este inventario lo
  prueba con un monto no dispensable a proposito. Su objetivo es acreditar que
  el endpoint existe y autentica, no repetir la demostracion funcional que
  viene a continuacion; con un monto valido consumiria el saldo de la cuenta y
  dejaria sin caso exitoso a esa demostracion, que es donde el rechazo y la
  autorizacion se ven juntos.

==============================================================================
 OPERACION CRITICA: RETIRO (solo el canal cajero)
==============================================================================

  monto no dispensable (7.500)               HTTP 400
  sobre el tope de la operacion (300.000)    HTTP 400
  monto valido (10.000)                      AUTORIZADO             saldo restante: 2000,00

  Las dos primeras reglas -multiplo de 10.000 y tope por operacion- son del
  CANAL y viven en el BFF del cajero. La validacion de saldo suficiente es del
  BANCO y vive en el modulo comun: cualquier canal futuro la hereda, mientras
  que las del cajero no se le imponen a nadie mas.

==============================================================================
 COHERENCIA ENTRE CANALES: UN RETIRO, TRES VISTAS
==============================================================================

  Retiro efectuado por el cajero: 10.000
  Saldo antes / despues        : 12.000  ->  2.000

  canal    endpoint consultado DESPUES del retiro                saldo
  --------------------------------------------------------------------
  web      GET /api/web/cuentas/146                              2.000
  movil    GET /api/movil/cuentas/146/resumen                    2.000
  cajero   GET /api/cajero/saldo                                 2.000

  Los tres coinciden. Ninguno de los BFF sabe de la existencia de los otros
  dos: lo que comparten es el modulo de dominio y la base, y cada uno decide
  por su cuenta cuanto de eso expone y con que forma. Eso es el patron.

  Notese que cada canal lo informa a SU manera y no todos exponen lo mismo:
  el web lo entrega dentro de una ficha de 13 campos con agregados anuales,
  el movil dentro de un resumen de 4, y el cajero solo, en 43 bytes. El dato
  es uno; la representacion es del canal.
